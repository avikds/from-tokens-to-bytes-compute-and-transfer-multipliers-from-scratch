From Tokens to Bytes: Compute and Transfer Multipliers from Scratch

How it was built

Part 1: One Corpus, One Unit

The mixed corpus every model in this project reads (English, code, math and six languages in train, nine unseen languages held out), and bits per byte, the only loss that compares a byte model with a token model.

Part 2: Three Ways to Read the Same Bytes

Raw bytes, BPE with a GPT-2-style pretokenizer, and BPE with no pretokenization (BPE-NP), all built from one vectorized trainer and one encoder, then compared on how many bytes each token carries in every domain.

Part 3: A Toy Ladder and Causal FLOPs

One number per model: the depth L fixes width, heads and FFN size as in the posts' ladder (scaled down), and a causal FLOP count turns a compute budget into a number of training steps for any encoding.

Part 4: Small Transformers in tinygrad

One pre-norm Transformer for all three encodings (only the vocabulary and the context differ), a warmup-stable-decay schedule, a TinyJit training loop with AdamW, and the standard validation bits per byte.

Part 5: Byte Probabilities from a Token Model

Prompt-and-answer excerpts from held-out languages, and two ways to score an answer with a token model: the standard canonical calculation, and the marginal one that sums over every valid token sequence covering the prompt boundary (the ByteSampler construction).

Part 6: Compute-to-Loss

An iso-FLOP sweep runner that trains every size at every budget and records validation and held-out losses, a power-law fit on the compute-optimal frontier, and the compute multiplier between two fitted laws.

Part 7: Loss-to-Loss and the Verdict

The loss-to-loss curve each encoding's two fitted laws imply, the posts' three-step loss-to-loss compute multiplier, a check that off-frontier runs sit on the same curve, and one function that reads off which encoding wins on compute and which on transfer.
